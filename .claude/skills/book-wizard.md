# Book Wizard Skill

CLI-driven workflow that automates the FunBookies wizard UI, pausing at each phase for user review and approval.

## When to Use

Use `/book-wizard` when creating a new book through the wizard interface. This skill:
- Opens the wizard in Chrome
- Fills in form fields automatically
- Triggers generation steps
- Pauses at each checkpoint for user review
- Shows snapshots/screenshots of progress

## Usage

```
/book-wizard <level> "<concept>" "<setting>"
```

Examples:
- `/book-wizard B1 "A cat naps in the sun" "cozy house"`
- `/book-wizard B2 "A puppy finds a lost ball" "sunny backyard"`
- `/book-wizard B4 "A frog helps a crab" "mossy pond"`

## Prerequisites

1. Chrome browser must be open with DevTools debugging enabled
2. The chrome-devtools MCP server must be connected
3. User should be ready to review and approve each phase

## Workflow Steps

### Phase 1: Concept Input

1. Navigate to wizard:
```
mcp__chrome-devtools__navigate_page url="https://funbookies.com/wizard/"
```

2. Wait for page load, then take snapshot:
```
mcp__chrome-devtools__take_snapshot
```

3. Fill the form fields:
```
mcp__chrome-devtools__fill uid="<levelSelect uid>" value="<level>"
mcp__chrome-devtools__fill uid="<conceptInput uid>" value="<concept>"
mcp__chrome-devtools__fill uid="<settingInput uid>" value="<setting>"
```

4. Click "Generate Outline" button

5. Wait for loading to complete

6. **CHECKPOINT 1**: Take snapshot and ask user:
   - Show the generated outline
   - Ask: "Review the outline. Would you like to proceed?"

### Phase 2: Outline Review

1. User can edit beats directly in the wizard UI if needed

2. When user approves, click "Expand to Full Story" button

3. Wait for loading (may take 10-20 seconds)

4. **CHECKPOINT 2**: Take snapshot showing the split view with story text and scene descriptions
   - Ask: "Review the story and scenes. Ready to continue?"

### Phase 3: Story Review

**New features:**
- "Regenerate Scenes (AI)" button - Uses LLM to rewrite all scene descriptions
- LLM-based validation when clicking "Continue to Reference"

1. If scenes look incomplete or generic, click "Regenerate Scenes (AI)"
   - This calls `/api/enhance-scenes` which uses Claude to write proper scene descriptions

2. User can edit text and scenes in the split view

3. When user approves, click "Continue to Reference" button
   - Wizard validates using LLM (`/api/validate-book-v2`)
   - Shows any continuity issues or scene quality problems

4. **CHECKPOINT 3**: If validation passes, take snapshot of reference phase
   - Ask: "Ready to generate the reference image? (~$0.15)"

### Phase 4: Reference Image

**Simplified:** The reference prompt is now generated by an LLM that reads the entire book context. No more metaprompt templates or regex extraction.

1. The wizard automatically generates a reference prompt using `/api/generate-ref-prompt`
   - Claude reads all pages and scenes
   - Writes an appropriate 9-panel reference prompt
   - No placeholders or templates needed

2. Take snapshot and review the generated prompt in `#referencePrompt`

3. **Model Selection**: Choose from dropdown `#refModelSelect`:
   - `nano-banana-pro` ($0.15) - Default, best quality
   - `gemini-flash` ($0.04) - Fallback if nano-banana-pro is down
   - `gemini-3-pro` ($0.07) - Alternative

4. Click "Generate Reference" button (`#genRefBtn`)

5. Wait for image generation (30-60 seconds)

6. **CHECKPOINT 4**: Take screenshot showing the reference image
   - Ask: "Does this capture the character correctly? Approve to continue."

7. When user approves, click "Approve & Continue" button (`#approveRefBtn`)

### Phase 5: Page Images

1. Take snapshot showing the page images grid

2. **CHECKPOINT 5**: Ask user:
   - "Ready to generate all page images? (~$0.03 each)"

3. Click "Generate All Pages" button (`#genAllPagesBtn`)

4. Monitor progress (watch `#pageProgress` for updates)

5. **CHECKPOINT 6**: Take screenshot showing completed page images
   - Ask: "Review the images. Continue to final review?"

6. Click "Continue to Review" button (`#phase5NextBtn`)

### Phase 6: Publish

1. Take snapshot showing review summary

2. **CHECKPOINT 7**: Show the quality checklist and ask:
   - "Review the book. Ready to publish?"

3. Optionally open the reader preview:
```
mcp__chrome-devtools__click uid="<readerLink uid>"
```

4. When user confirms, click "Complete & View Book" button

## Error Handling

### Service Unavailable (Error 3002)
If you see `{"code":3002,"title":"External service request failed"}`:
- Switch model from `nano-banana-pro` to `gemini-flash` in dropdown
- The model selector is at `#refModelSelect` (single-ref) or `#multiRefModelSelect` (multi-ref)

### Validation Failures
- LLM validation may flag continuity issues (character states, props)
- Issues shown in `#validationMessages`
- User can fix scenes or click through if issues are minor

### Loading States
- Phase 1: `#phase1Loading`
- Phase 3: `#phase3Loading`
- Phase 4: `#phase4Loading`

## Tips

1. **Take snapshots frequently** - Show user what's happening
2. **Use LLM features** - "Regenerate Scenes (AI)" fixes most scene issues
3. **Check model availability** - Have gemini-flash as fallback
4. **Pause at checkpoints** - Always ask before expensive operations ($)
5. **Handle timeouts** - Image generation can take 60+ seconds

## How It Works (Simplified)

The wizard now uses LLM calls instead of complex logic:

| Step | Old Way | New Way |
|------|---------|---------|
| Reference prompt | Regex + templates | Claude reads book, writes prompt |
| Validation | State machine rules | Claude checks continuity |
| Scene generation | Python scripts | Claude writes all scenes |

**Pattern:** Send context to Claude → Get semantic understanding → No regex needed
